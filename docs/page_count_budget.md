### microCMS転送量の目安式
記事ページ1PVあたり画像（アイキャッチ+チャートPNG）約150KBとすると、無料枠20GB/月 ≈ **約13万PV/月** まで。転送量はページ数ではなくトラフィックに比例するため、PVが月10万を超え始めたら監視を開始する。

## 3. クロールバジェット（本当の予算問題はこちら）

- GSC実績（2026-08-12、当時約5,000ページ規模）: 「検出-未登録」149件＋「クロール済み-未登録」104件 = **253件が滞留**。
- 新規・小規模サイトへのGooglebotの実効インデックスペースは日数十〜数百ページ。**増加30ページ/日はこれと同オーダー**であり、薄いページが割当を食うとbacklogは拡大する。
- 内訳の問題: インデックスさせたい「価値ページ」（記事740＋記事あり銘柄約300＋開示2件以上の投資家約1,950 ≈ 3,000）に対し、クロール可能ページは7,300。**割当の約4割が薄いページ（開示1件の投資家992、日付ページ282、記事なし銘柄など）に流れる構造**になっている。この比率は放置すると悪化する（投資家+170/月のうち例年3割強が開示1件のまま）。

### 対策案（優先度順）

1. **P1: sitemapから開示1件のみの投資家を除外**（`sitemap.ts` で `holdingCount >= 2` にフィルタ）。ページ自体は残すのでリンク到達は可能なまま。
   **→ 実装・本番反映済み**（`a7935506 fix(seo): インデックス未登録の主因(クロール枠の枯渇)に対策`。定数 `SITEMAP_MIN_FILER_HOLDINGS` として `kujira-watch/src/app/sitemap.ts` に実装）。
2. **P2: 投資家ページの薄さ解消を「開示2件目が出たときにsitemap入り」という運用に**。**→ P1の副作用として自動達成済み。**
3. **P3: `/date/[date]` の古いページはsitemapから除外**（+20/月で増え続ける）。月別ページをハブとして残せば導線は保たれる。**→ 未実施**（2026-08-19時点で本番sitemapに235件登録されたまま）。
4. **P4: 記事なし銘柄ページ（約2,600件）は既に薄いコンテンツ対策済み**（事業内容backfill・銘柄別要約文、2026-08-15）。効果はGSCで数週間観察してから追加判断（[[feedback_seo_indexing_wait]] 遵守）。
5. **P5（金銭・別件）: AdSense収益化を本格化するならVercel Pro $20/月を予算化**（Hobbyの非商用規約対応）。
