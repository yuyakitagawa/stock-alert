# AdSense審査「有用性の低いコンテンツ」対応

2026-08-24 に AdSense 審査で不承認（理由: 有用性の低いコンテンツ）。
Google のポリシー3本（コンテンツの最小要件 / 独自性のある質の高いコンテンツ /
ウェブマスター品質ガイドライン: 質の低いコンテンツ）に照らして原因を実測し、改善する。

## 実測した原因（2026-08-24）

| ページ種別 | 件数 | 本文の実態 | 判定 |
|---|---|---|---|
| 記事 `/articles/[id]` | 976 | **中央値455字・100%が1,000字未満・98%が600字未満** | 最小要件に不足 |
| 銘柄 `/stocks/[code]` | 664 | 記事1件だけが482件(73%) | cookie cutter |
| 取引日 `/date/[date]` | 223 | 記事1件だけが87件、2件以下が149件 | thin content |
| 投資家 `/investors/[filer]` | 2,972 | 解説文なしが2,152件(72%)、開示1件のみが1,002件 | cookie cutter |

- サイト全URL 4,756件のうち **75%が自動生成の集約ページ**。
- 記事生成プロンプトは「650〜900字」と指示しているのに実出力は455字で、指示自体も薄い。
- 文の完全一致（コピペ）は無いが、全記事が「①誰が何%取得 ②推定金額と株価 ③※推測」の
  3段落テンプレートで、Google の "cookie cutter" に該当する。

## 対応

- [x] 1. 薄い自動生成ページを noindex にする（コスト0）
  - [x] 取引日: 記事3件未満は noindex（223→index 74件）
  - [x] 投資家: 解説文なし or 開示1件のみは noindex（2,972→index 567件）
  - [x] 銘柄: 記事1件のみ かつ 事業内容の説明なしは noindex（664→index 637件）
  - [x] sitemap を noindex 判定と一致させる（判定は lib/pageIndexability.ts に集約）
- [x] 2. 記事生成プロンプトを厚くする（新規記事）
  - [x] Supabase の既存データから独自の事実を追加投入（`build_context_facts()`）
        保有の積み上げ履歴 / その投資家の他の保有銘柄（業種つき） / その銘柄の他の大株主 /
        開示日時点のPER・PBR・52週レンジ位置・業種。すべて point-in-time。
        ※提出者の過去リターン実績は `filer_win_rate` テーブルが既に廃止されており、
          都度計算が必要なため今回は見送り（効果が要るなら別途）
  - [x] 目標文字数 650〜900字 → 1,300〜1,700字（検証: 455字 → 800〜1,206字）
- [ ] 3. 既存976記事のリライト（**オーナー指示によりAPIバッチではなくClaude Codeが直接執筆**）
  - [x] `tools/export_article_fact_cards.py`: 記事1本ぶんの事実をJSONで書き出す
  - [x] `tools/apply_rewritten_articles.py`: 書いた本文をPATCHで反映（反映前にlogs/へバックアップ、
        既存より短い本文は弾く）
  - [x] `tools/rewrite_thin_blog_articles.py`（APIで書かせる版）も周辺事実を渡すよう修正済み。
        今回は使わないが、将来まとめて流したくなったときのために残す
  - [x] **72件完了**（取引日の新しい順）。実測 352〜697字 → 554〜1,177字
  - 反映済みIDは `logs/rewritten_article_ids.txt` に追記され、事実カードの書き出し側が
    それを読んで候補から外す（中断しても再開できる）
  - [ ] 残り964件（1バッチ8〜12件・1バッチにつき1往復。全件だと80〜120往復かかる）
  - **リライト不能な記事が全体の約20%**（実測107件中22件）。誤報になるため書かずに
    `logs/unwritable_article_ids.txt` へ退避し、最後にまとめてnoindexか削除を判断する:
    - 変化幅0pt＝何がどれだけ動いたのか書けない
    - 保有比率も変化幅も1%未満＝「大量保有報告書」として示せる中身が無い
      （例: 野村證券0.03%、横河電機0.33%で推定898億円という桁の合わない金額）
  - 同一開示で**記事が2本ある重複**を発見（スタートライン477A）。`logs/duplicate_article_ids.txt`
  - **リライト不能な記事は削除した（オーナー判断、2026-08-25）**。計74件。全フィールドを
    `logs/deleted_articles_*.json` へ退避済み（microCMSへ再投稿すれば復元可）
    - 保有比率も変化幅も1%未満で示せる中身が無いもの 58件
    - 変化幅0ptで売買量が不明かつ保有も5%未満のもの 15件
    - 同一開示から二重生成された重複 1件
    - **保有5%以上のものは削除せず救済**（17件）。変化幅を主張しない書き方に直し、
      データと矛盾するタイトルも差し替えた（例: メタウォーター9551は保有19.48%なのに
      タイトルが「17.5%から低下」だった）
  - 提出者を特定できず材料が作れない記事が182件あったが、記事側のfilerNameとタイトルから
    一意化する `resolve_filer()` を入れて**154件を救済**。残り28件はリライト不能
  - 事業内容が**別会社の説明**になっている例を発見（LIFULL 2120＝不動産情報サイトなのに
    「葬儀・終活関連サービス」）。該当記事では事業内容に触れずに書いた

### 追加で見つけて直したもの
- 事業内容(`jpx_stock_list.description`)の64銘柄に、web検索の`<cite index="7-1">`タグが
  そのまま保存され、銘柄ページ・`/trending`・metadataに文字として表示されていた。
  生成側で除去するよう修正し、既存データも一括修正済み（`tools/strip_html_from_descriptions.py`）。
- [ ] 4. 反映確認 → AdSense に再審査をリクエスト
