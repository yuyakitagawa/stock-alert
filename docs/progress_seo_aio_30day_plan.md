# kujira-watch SEO/AIO 30日改善計画（外部アドバイス第3弾の反映）

最終更新: 2026-08-15
対象: `kujira-watch/`（https://kujira-watch.com/ ）+ `web/publish_blog_articles.py` + `web/x_client.py`

## 0. 前提と位置付け

2026-08-15に受けた外部SEO/AIOアドバイス（課題10項目＋30日プラン）を、現状のコードベースと
突き合わせて「実装済み」「本当のギャップ」に切り分けた実行計画。
過去の同種計画（`progress_blog_seo_aio.md` / `progress_discover_seo_plan.md` /
`progress_seo_indexing.md` / `progress_stocks_thin_content.md`）と重複する作業はやらない。

**結論**: アドバイスの🔴S課題①②③⑥（個別ページ・銘柄ページ・投資家ページ・内部リンク）は
**大部分が実装済み**。本当のギャップは「④タイトルの検索クエリ設計」「⑤記事内の構造化された
答え（ファクトボックス）」「⑦ランキングの拡充」「⑨SNS日次サマリー」「⑩KPI計測(GA4)」の5点。
30日はこの5点に集中する。

## 2. 30日フェーズ計画

### P0: 計測基盤（Day 1〜3・効果測定の前提）
- [ ] GA4導入（Stage 7の再開）。**ユーザー作業**: GA4プロパティ作成と測定ID(`G-…`)の共有。
      実装は`@next/third-parties`の`GoogleAnalytics`を`layout.tsx`に追加するだけ。
- [ ] KPI定義を固定（本計画の効果判定に使う）:
  - GSC: クリック数 / 表示回数 / CTR / 平均掲載順位（週次で記録）
  - ページ種別PV: 記事 / `/stocks/*` / `/investors/*` / ランキング（GA4のページパス別）
  - 回遊: ページ/セッション
- [ ] ベースライン値をこのファイルに記録してから施策を開始する（比較対象が無いと効果判定不能）。

### P1: 記事テンプレートの検索クエリ化＋ファクトボックス（Day 4〜10）
対象: `web/publish_blog_articles.py`（生成側）+ `kujira-watch/src/app/(ja)/articles/[id]/page.tsx`（表示側）

- [ ] **タイトルのテンプレート化**: LLM自由生成をやめ、決定的テンプレに変更。
      `{銘柄名}（{コード}）、{提出者名}が保有比率{X}%に{引き上げ/引き下げ}｜大量保有報告書`
      （40字超過時の短縮ルールも決定的に定義。titleEnも同様にテンプレ化）
- [ ] **冒頭アンサー文の強制**: 本文プロンプトに「1文目は『{銘柄名}（{コード}）について、
      {提出者名}が保有比率を{X}%まで{引き上げ/引き下げ}たことが大量保有報告書から分かりました。』
      で始める」を追加（AIO: 検索クエリへの直答）。
- [ ] **ファクトボックス（今回のポイント）**: 記事ページに構造化ブロックをフロント側で決定的に
      レンダリング（LLM不使用）。項目: 保有比率 / 前回比（bodyから抽出不可のためmicroCMSに
      `ratioChangePct`数値フィールドを追加し`publish_blog_articles.py`から送る）/ 推定金額 /
      方向（買い増し・売却バッジ既存流用）/ 投資家分類 / 注目理由（`attentionReasons`既存）。
- [ ] **出典ブロックの統一**: ファクトボックス直下に「情報源: EDINET大量保有報告書 /
      提出日: {dealDate} / 記事公開: {publishedAt}」を定型表示（E-E-A-T残タスク）。
- [ ] microCMSスキーマ追加（**ユーザー作業**）: `ratioChangePct`（数値）。ついでに
      README記載済みの未作成フィールド`filerName`もこの機会に作成し、突合ロジック依存を解消する。
- [ ] テスト更新（`tests/test_publish_blog_articles.py`）+ README更新（同一コミット）。
- [ ] 効果測定: 適用後の新規記事のGSC掲載順位/CTRを、適用前1週間の記事と比較。

## 3. やらないこと（明示）

- **SEO記事の量産・別途特集記事の執筆**: アドバイス自身も「DB型SEOが向いている」と結論。
  既存のデータパイプライン（1開示→記事+銘柄+投資家+日次+ランキング更新）を強化する方向に集中。
- **銘柄ページの期間別サブページ（/stocks/8151/30d等）**: 薄いコンテンツの量産になり、
  現在進行中のインデックス未登録問題（`progress_seo_indexing.md`）と逆行するため作らない。
- **既存記事104件の一括リライト**: 2026-08-14にユーザー判断で放置と決定済み。P1のテンプレは
  新規記事のみに適用（`tools/rewrite_thin_blog_articles.py`は残置済み、必要時に`--ids`で再開）。
- **カテゴリ→投資家個人ページの新設**: `/investors/[filer]`が既に存在するため不要。

## 4. 効果判定の規律

- 各フェーズのマージ前に `npx tsc --noEmit` / `npm run lint` / `python3 tests/test_*.py` で
  デグレ確認（CLAUDE.md §8）。
- SEO施策はバックテスト不能のため、**GSCクリック数・表示回数・対象ページ種別PVの前後比較**を
  マージ後の効果判定KPIとする。インデックス反映は数日〜数週間かかる前提で急かさない
  （[[feedback_seo_indexing_wait]]の運用に従う）。
- 各ステップ完了ごとに本ファイルの `[ ]` を `[x]` に更新してコミットする（CLAUDE.md §6）。
