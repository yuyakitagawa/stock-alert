## 1.5 実測で見つかった漏れ（2026-08-29）

`tools/gsc_report.py`の「表示のあったURL」924件（/en除く）に本番のHTTPステータスを突き合わせた結果:

| 状態 | URL数 | 表示 | クリック |
|---|---|---|---|
| 200 | 605 | 2,147 | 106 |
| **404** | **194** | **698** | **25**（全クリックの18%が「ページが見つかりません」に着地） |
| 308 | 125 | 282 | 4 |

- [ ] **A. 削除済み記事の404（124件・表示526・クリック20）**。低価値/重複/誤報記事の削除
      （8/18の129本ほか）でURLが消え、検索結果に残ったまま404を返している。
      削除ログ（`logs/deleted_*.json`）に`stockCode`が残っており**116件は`/stocks/<code>`へ
      恒久リダイレクトで回収できる**。今後の削除でも同じことが起きるため、削除時に
      リダイレクト先を記録する仕組みが要る。
- [x] **B. 銘柄ページ47件・投資家ページ23件の404（表示145・クリック5）は仕様どおりだった**。
      PR #290「薄い集約ページをnoindexではなく404にする」（2026-08-29 19:02 mainマージ、
      オーナー判断）で、`pageIndexability.ts` の条件を満たさない `/stocks/[code]`・
      `/investors/[filer]`・`/date/[date]` は404を返すようになった。当初「本番だけ404、
      ローカルは200」と見えたのは、こちらのブランチがそのPRより前だったため。
      本番の`/api/stocks/search`が記事の無い銘柄を返さないのも同じ変更（検索APIも公開集合で絞る）。
- [ ] **B'. 404にした集約ページのうち、検索需要があるものの扱い**（未決）。
      上記70URLは28日で表示145・クリック5を取っていた。薄いページを消す方針は維持しつつ、
      検索から来ている分は404ではなく上位ページ（例: 銘柄→`/trending`や記事、
      投資家→`/investors`）へ引き継ぐ選択肢がある。`deleted_article_redirects` と
      同じ仕組みを流用できる。**オーナー判断待ち**（AdSense審査対応との兼ね合い）。

  実測（2026-08-29、リダイレクト登録後）: 登録257件のうち引き継ぎ先の銘柄ページが公開中なのは
  131件（51%）。検索表示のあった削除済み記事124件で見ると、銘柄ページへ引き継げるのは52件
  （表示265・クリック10/28日）で、残り72件（表示288・クリック10）は引き継ぎ先の銘柄ページ自体が
  非公開だった。このため表示側で「銘柄ページが非公開なら**同じ銘柄の生存記事**へ送る」
  フォールバックを入れている（`resolveStockTarget()`）。
- [x] C. 旧・日本語URLの投資家ページ125件は308リダイレクト（表示282）。仕様どおりで、
      Googleの統合待ち。対応不要。
- [x] D. `/en`（738表示・全体の21%）は2026-08-29の英語版廃止で日本語版へ308。仕様どおり。
