月次上限に到達（2026-08-23、復帰 2026-09-01 00:00 UTC）したため、定常コストと
バックフィルコストの両方を削る。調査結果と方針は本ファイル冒頭に記録し、

## 調査で判明した事実（2026-08-24 実測）

- 上限を消したのは定常運用ではなく **会社説明バックフィル**（8/15・8/18 に計4回）。
  `get_company_description` は Haiku + `web_search`(max_uses=3)。Web検索は
  **$10 / 1,000検索** ＋ 検索結果本文が入力トークンとして課金される（1検索 ≒ 6,000トークン）。
  1社あたり約 $0.05。4,489社の全件バックフィル1回で約 $225。
- **空文字（不明）を返した会社をキャッシュしていない**ため、同じ「不明」社群を
  バックフィルのたびにフル課金で再試行していた。
  jpx_stock_list 4,489社中 description あり 2,385社 / 未設定 2,104社。
  edinet_filer_classification 2,959件中 profile あり 820件 / 未設定 2,139件。
- `daily_log_review`（8/23追加）は **実行回数0** だが、9/1 以降は毎晩 opus-5 で走る。
  入力を実測すると 19 runs / **248,678文字**、うち **198,042文字（80%）が
  EDINET Blog Hourly 12本のほぼ同一ログ**。月 $17〜21 の見込み。
- 上限到達後も毎時実行が記事ごとにAPIを叩き続け、十数回失敗していた（課金はされないが
  記事が無言で欠落する）。

## A. daily_log_review の入力削減（月 $17-21 → $5前後）

- [x] 成功した run はログ本文を捨て、job/step のサマリのみ渡す
- [x] 同一ワークフローが1日に複数回走る場合は代表1本＋残りは1行に集約
- [x] `output_config.effort` を high → medium
- [x] 入力文字数の実測ログを残す（削減効果の追跡用）

**実測: 248,678 → 81,798文字（67%減）。EDINET分は198,042 → 34,270字（83%減）。**
- [x] テスト更新・追加

A4（失敗runが無い日はレビュー自体をスキップ）は**見送り**。A1〜A3で入力が8割落ち、
残りの節約は月$2程度にとどまる一方、Supabaseスナップショット由来の
UX/PdM/SEO観点のフィードバックが平常日に丸ごと失われるため割に合わない。
