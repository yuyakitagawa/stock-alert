# X(@kujira_watch) 運用ルール

自動投稿だけでは会話が生まれずアカウントが伸びない、というコンサル指摘（施策10、
`docs/x_post_improvement_1000.md` #181-190 / #601-610）に対する運用側のルール。
コードで担保できない部分をここに文書化する。

## 0. 自動投稿は週1本だけ（2026-08-30〜）

**残したのは土曜18:00 JSTの「1週間のまとめ」1本だけ**（`web/x_weekly_trending.py`＝
大口投資家の取引急増ランキング。直近7日とその前の7日を比較した週次集計で、
記事1本ごとの投稿ではない）。以下の3〜9章は、全面再開したときに効く運用ルールとして残す。

- 止めたもの: `x_post.yml` の5スケジュール（activists / followup / buyback / metrics /
  facts）と、`web/publish_blog_articles.py` から呼んでいた
  `post_top_articles` / `post_daily_summary`（＝記事1本ごとの投稿と日次サマリー）。
  手動実行（workflow_dispatch）は全ターゲット残っている。
- 根拠（2026-08-19〜08-29の実測）: 34投稿・総インプレッション43・いいね0・リポスト0・
  URLクリック1・フォロワーは10日連続0。1章に書いたとおりリーチの経路は
  「フォロワーのタイムライン」「X内の検索」「他チャネルからの流入」の3つしか無く、
  フォロワー0・被検索ゼロ・流入元ゼロで3つとも塞がっている。投稿を続けても
  時間では解決しない。
- **アカウントと既存投稿は消さない。** 「誤った投稿は削除しない」（4章）と同じ考え方で、
  過去の発信の記録を残す。再開の判断も後からできるようにしておく。
- **週1本だけ残す理由（E-E-A-T）**: Xはサイトの Organization スキーマの `sameAs` と
  `contactPoint`（`kujira-watch/src/lib/site.ts`）に入っており、実名・メールを公開しない
  運営方針の下では**唯一の連絡窓口**。`/about` も「速報は公式Xでも発信しています」と
  書いているため、投稿を完全に止めると運営者情報の記述が実態と食い違う。
  URL無しの投稿は $0.015/本なので週1本＝**月約$0.06**で、日次予算にも当たらない。
  頻度を上げるのは「届く先ができてから」（下の再開条件）。
- **再開条件**: サイト（kujira-watch.com）の自然検索が伸びて、**X以外からXへ人を送れる
  状態**になったら再開を検討する。それまでは投稿を増やしても3つの経路のどれにも乗らない。
- 全面再開の手順: `x_post.yml` に残り5つの schedule を戻し、`publish_blog_articles.main()`
  から `post_top_articles` / `post_daily_summary` を呼び直す（投稿処理は `web/x_client.py`
  にそのまま残してある）。

## 1. 手動の会話枠（週2回）
- **月曜と木曜**に各15分、Xを開いて以下を行う。
  1. 直近の自動投稿に付いたリプ・引用を確認し、24時間以内に返す
  2. 質問には事実だけで短く返す。投資判断を求める質問には「データ提供のみで投資助言はしない」と返す
  3. 誤りの指摘は最優先で対応する（訂正の手順は下記4）
- **こちらから他アカウントの投稿にリプライ・引用リポスト・メンションはしない**（2026-08-30、
  オーナー指示「向こうのタイムラインには出さないで」）。返信するのは**自分の投稿に付いたリプ**だけ。
  フォローはしてよい（相手のタイムラインには出ないため）が、そこから先の絡みに行かない。
- この制約により、リーチの経路は「検索で見つかる」「フォロワーのタイムライン」
  「他チャネル（YouTube・ブログ）からの流入」の3つだけになる。伸ばす施策はこの3つの中で考える。

## 2. 投稿してよい/いけない表現
- 使わない: 必ず／確実／絶対／買い時／推奨／暴騰／暴落／爆益
- 将来の株価・目標株価に言及しない。特定銘柄の売買を勧めない
- 事実（開示内容）と推定（金額の概算）を必ず書き分ける。推定には「推定」「約」を付ける
- 企業・個人への評価的な形容を書かない
- 開示時点の指標（PBR・ROE・配当性向）は数字だけを出す。「割安」「狙われやすい」等の
  評価語や、そこから導いた見通しは付けない（`web/x_insight.build_valuation_line`）

## 3. 投稿枠（自動。**現在動いているのは急増ランキングのみ**＝0章。他は全面再開時の想定）
| 枠 | 時刻 | 実装 |
|---|---|---|
| 記事投稿（注目枠・1回1件） | 平日 9-21時 JST 毎時 | `web/x_client.post_top_articles` |
| 訂正報告書（件数制限なし・既報へリプ） | 同上 | 同上 |
| 本日のクジラ（日次サマリー） | 平日 21:00 JST | `web/x_client.post_daily_summary` |
| 答え合わせ（3ヶ月前の開示のその後） | 水 21:00 JST | `web/x_followup.py` |
| 急増ランキング | 土 18:00 JST | `web/x_weekly_trending.py` |
| アクティビストの動き | 日 18:00 JST | `web/x_weekly_activists.py` |
| 動画クロス投稿 | 平日 19:30 JST | `video/publish_video.py` |

JST 8〜22時の外では自動投稿しない（`x_client.within_posting_hours`）。

## 4. 訂正・お詫び
- 誤った投稿は**削除しない**。同じスレッドに訂正をぶら下げる
- 重大な誤り（数値の桁・銘柄違い）は独立した訂正投稿を出す
- 原因はコード側のテストで再発防止し、`dev_log.md` に記録する

## 5. 炎上・障害時
- 相場急落日・災害時は投稿トーンを変えず、数字だけを淡々と出す
- 攻撃的なリプには反応しない（ミュート。ブロックは最終手段）
- 自動投稿を止める場合は GitHub Actions の該当ワークフローを無効化する

## 6. 効果検証
- フォーマット変更は**1度に1要素**だけ変える
- 各パターン最低10投稿・2週間を集めてから判断する（`web/x_metrics.py --report`）
- **最終指標はフォロワー数**（`x_followers`、日次記録）。投稿の型を判断する中間指標は
  プロフィールクリック率（`user_profile_clicks / impressions`）→ 平均インプレッション →
  平均ブックマーク → リンククリックの順。いいね数は判断に使わない
- フォロワーは「インプレッション→プロフィールクリック→フォロー」の順にしか増えない。
  伸びない時はどの段で落ちているかを先に特定する（リーチ不足か、プロフィールに飛ばないか）
- 悪化した変更はコードごと戻す。結果は `dev_log.md` に残す

## 7. URLは投稿に入れない（2026-08-22〜）
X APIの従量課金はリンク入り投稿が$0.20/本（リンク無し$0.015の13倍）で、投稿コストの
ほぼ全部がこの加算だった（8/19〜20の14本で$2.2、クレジット枯渇）。自己リプライにURLを
置いてもそのリプライが$0.20になるため回避にならない。全投稿の末尾を
「詳細はプロフィールのリンクから」に統一し、URLはプロフィールの固定リンク1本に集約する。
プロフィールのリンクには `?utm_source=x&utm_medium=profile` を付け、GA4でX経由を識別する。
`x_posts.variant` は `no_link` で記録される。

## 8. YouTubeの誘導URLもUTMで識別する
動画の概要欄のリンクはコード（`video/post_text.py` / `video/youtube_client.py`）が
`?utm_source=youtube&utm_medium=social&utm_campaign=auto_video` を付けて出している。
チャンネルページのリンク欄（YouTube Studio → カスタマイズ → 基本情報 → リンク、オーナーが手動設定）には
Xのプロフィールと同じ形で `https://kujira-watch.com?utm_source=youtube&utm_medium=profile` を設定し、
GA4で概要欄経由（social）とチャンネルページ経由（profile）を分けて見る。
